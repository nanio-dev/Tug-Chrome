# 2026-11-15 改善记录

## 改动

1. HTTP 有界、均衡 Range 队列取代运行时切割；HTTP/1.1 限制有效工作者，复用每个工作者的缓冲，不重复下载已分配范围。
2. 严格核对 Range/长度/验证器；只重试可恢复网络错误，加入网络空闲超时并在失败后等待整组请求收敛。
3. 接收、写入和已同步位置分离；持久化只使用已同步检查点。新文件重置与续传保留区分，数据库快照串行化。写盘/同步/配额/Worker/数据库失败不会变成成功或无限重新排队。
4. 增量 SHA-256、完整令牌欠账和可取消限速；校验/保存为独立任务状态，暂停保存后可重试缓存。
5. BT 文件勾选改变时失效跨文件完成标记；缺失缓存不作为全零内容输出。保存状态按文件持久化，中途失败只重试尚未保存文件。
6. Agent 协议 2：Native Messaging 能力凭据、受限 CORS、实际路径根目录检查、无 shell 文件打开、临时文件同步后原子发布。
7. 文件名遵循用户指定优先、服务端建议其次；窄窗口布局、旧 Agent 更新提示、Tracker 自定义空列表行为修复。

## 性能复测

同一 D 盘、同一浏览器配置、本地 HTTP/1.1、同一个 128 MiB 随机文件，旧版 `5a3b240` 与当前工作区交替运行，每组 3 次中位数，单位 MiB/s。轮次交替切换版本和连接数顺序，减少顺序漂移。下载计时包含写盘同步，不包含最终系统导出；全部 24 个样本 SHA-256 正确。

| 场景 | 原 Web 8连接 | 改善后 8连接 | 原 Web 32连接 | 改善后 32连接 |
|---|---:|---:|---:|---:|
| 不限速 | 277.1 | 315.5 | 252.3 | 312.5 |
| 每连接限速 | 22.08 | 23.10 | 14.57 | 23.24 |

两种配置表现接近，消除了 32 配置明显落后于 8 的情况。32 配置的不限速吞吐约提升 24%，每连接限速场景约提升 60%；不限速场景服务端响应数据由约 198.5 MiB 回到 128 MiB，请求中位数由 129 次减至 19 次。之前系统盘试跑与原评估的跨轮次数字不作为本表对照。测试只说明本地 HTTP/1.1 的行为；没有承诺公网、HTTPS 或 HTTP/2/3 的同等增幅。

原生 HTTP 对照仍显示 HTTP/1.1 大并发潜力。Agent 的原生 HTTP 通道在本轮完成可行性评估，尚未接入产品：直接接管会影响 Cookie/代理、输出文件归属、取消和恢复，需要先定义由插件指定区间、Agent 回报已提交字节的协议。当前产品仍走浏览器 HTTP → OPFS → 系统导出，不引入另一套下载队列。

## 升级兼容性

- 插件和 Agent 应同时更新。新版拒绝无授权的协议 1 Agent，旧版会显示更新提示；重新加载插件后通过 Native Messaging 配对。没有更改产品版本号或发布 tag。
- 旧版 HTTP/BT 未完成检查点没有可信提交标记，会重新验证或重新下载；已完成任务及已保存的系统文件不被迁移删除。
- 旧版 BT 中途导出失败的记录缺少逐文件保存状态，升级后可能产生正确内容的重复文件；新版重试已有逐文件状态，不重复导出已记录的文件。
- 若工作中的 OPFS Worker 崩溃，需要重新加载扩展再恢复，避免在无法确认同步结果时悄悄切换后端。
- 文件发布与任务状态持久化之间仍不是跨系统事务：若恰在最终文件已发布、结果尚未持久化时退出，可能留下正确内容的重复输出。不会通过重建零缓存来“完成”缺失文件。

## 验证入口

43 项 Node 测试、5 项真实浏览器测试、1 项真实 Agent 集成测试、5 项 Rust 测试、Clippy 和生产构建通过。本地 HTTPS/HTTP/2 已验证 32 工作者复用；1 GiB 文件通过真实 OPFS 下载与增量 SHA-256 校验。完整覆盖与环境要求见 [testing.md](testing.md)。真实公网 BT、HTTP/3、代理、更大的多 GB 和整机断电仍需专项验证。

## 公网补测：用户提供的两个下载地址

2026-11-15 同机独立 Chromium 配置、8 工作者、每组 30 秒：默认 HTTP/2 的 GitHub / Android Studio 窗口均速分别约 187 / 42 KiB/s；Desktop 同源原生 HTTP 核心通过系统代理约 912 / 1239 KiB/s，实际协商 HTTP/1.1。同一插件仅在测试配置中关闭 HTTP/2 后约 636 / 664 KiB/s。20 秒重复样本也出现明显差距，并确认 HTTP/2 复用一个 connectionId、HTTP/1.1 使用六条连接。

这补测表明上述本机优化没有解决这两个公网地址的主要瓶颈。证据指向当前网络中的协议/连接拓扑差异，不能推导为 HTTP/2 普遍低效；OPFS 等待很少，无落盘 fetch 也慢，no-store 没有一致改善。机器启用了 Mihomo 系统代理与 Meta TUN，关闭显式代理也不能证明绕过透明代理，尚不能区分 CDN 策略、拥塞和代理流控的具体责任。测试为时间窗采样，不是整文件完整性验收。

后续优先补协议与传输诊断，并设计 Agent 原生 HTTP 通道；当前 Agent 尚未接管 HTTP 下载。浏览器 fetch 无法按请求强制 HTTP/1.1 或创建独立连接池，单纯增加工作者不能保证获得原生多连接收益。

## Agent 启动专项修复

修复首次运行仅轮询健康却未获取凭据的闭环缺口，新增明确配对步骤、共享 Native Messaging 握手、连接保留与纯插件模式释放；安装状态写入 session 以便 Service Worker 恢复。安装包改为随当前构建提供。注册逻辑按实际值修复迁移路径，BT 延迟初始化，活动导出避免空闲退出，启动失败增加日志，Agent 导出失败不再静默回退重复保存。

本机实测装着旧协议，且 Chrome/Edge/360 X 注册路径指向下载目录的空授权清单。实际系统更新操作被自动审批拒绝，旧实例未替换，需要用户退出旧进程后运行当前构建并重新配对。

128 MiB 每组 3 次，本地同 D 盘 HTTP→OPFS→Agent 落盘均完成哈希校验，8/32 配置的完成总吞吐中位数约 201.5/200.8 MiB/s；网络下载仍走浏览器，Agent 没有接管 HTTP 源站。另有两份 1 GiB 完整输出校验通过。这些受控本机数据不代表公网吞吐。

## 安装测试流程调整

按开发测试要求，恢复 GitHub raw 固定地址并附加时间戳，构建后连同 Agent 二进制推送。安装文件名携带扩展 ID，迁移时继续传递，以便正常下载启动自动授权；通用文件首次运行保留明确授权后备入口。已配对连接先静默握手；连接成功统一刷新并自动关闭弹窗。此前“随扩展打包安装”的方案已被此流程替代。

## 恢复安装缓存与 Agent 生命周期

撤销保存阶段使用远程 URL 的改动，下载完成后保持本地 Blob 缓存且无固定过期计时，保存不再重复下载；增加保存状态主动检查、休眠后状态恢复与超时可重试。恢复普通文件名与开放 /register，网页来源仍拒绝、控制接口继续凭据校验，连接界面移除协议授权跳转。手动启动替换已知旧 Agent 并迁移到 AppData，日常握手复用已有进程；无任务空闲 120 秒退出，不被 Native Messaging 端口或健康查询阻止。隔离进程测试覆盖旧进程替换、迁移/清理及缩短超时下的退出。

## 2026-11-16 导出与卸载修复

修复真实 Offscreen 文档只有 runtime API、无法读取后台 session 凭据导致的保存失败。Offscreen 通过仅允许其 URL/扩展 ID 的私有 RPC 让后台自动唤醒并取得凭据；401 在服务端尚未执行操作时自动刷新重试一次。新增真实扩展 HTTP→OPFS→隔离 Agent 导出测试，包含进程重启和凭据轮换，均核对系统输出哈希；没有额外用户激活步骤。

卸载不再依赖 cmd/ping 延迟删除：将正在运行的已安装二进制移出常驻目录，清理目录并确认后返回成功，独立隐藏清理进程在 Agent 退出后删除临时二进制。卸载失败返回错误并显示，成功时清理凭据、切回独立模式，阻止后台刷新再次唤醒。隔离实际进程测试确认常驻目录及临时文件均消失。

## 关闭 Agent 后的小窗行为

小窗等待设置加载后再决定是否恢复 Agent 安装状态；独立模式不查询/恢复安装弹窗，切换为独立模式时立即隐藏弹窗并取消旧查询回调。新增回归覆盖残留 need_pairing 状态和异步查询晚于关闭设置返回的情况。

## 多文件种子的完成操作

任务视图增加实际选择的输出文件数量。管理面板与小窗仅在 HTTP 或明确单选一个文件的种子任务中显示打开文件；多选/未知数量只保留打开文件夹。客户端与后台同时限制多文件打开请求，单选采用对应逐文件导出路径/下载 ID。回归覆盖多文件种子的单选、多选和未知元数据，以及两个界面的按钮行为。
